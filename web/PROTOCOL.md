# Webes megtekintés – protokoll (v1)

The browser and the phone share one encrypted message through a relay that cannot read it.

1. **Browser** generates a one-time ECDH P-256 key pair (private key non-extractable) and a
   22-character session id (16 random bytes, base64url). It shows a QR code with

       https://<host>[/<prefix>]/l#<sid>.<base64url(raw public key, 65 bytes, 0x04||X||Y)>

   and long-polls `GET /api/relay/<sid>`.
2. **Phone** (the DentHub-Brush app) scans the QR code, shows the host name, asks for Face ID /
   fingerprint, builds the statistics snapshot (JSON, `WebSnapshot`), and seals it:
   - ephemeral ECDH P-256 key pair; `shared = ECDH(phone_priv, web_pub)` (32-byte X coordinate)
   - `key = HKDF-SHA256(ikm = shared, salt = utf8(sid), info = "fogmosas-web-v1", L = 32)`
   - `ct = AES-256-GCM(key, nonce = 12 random bytes, aad = utf8(sid), plaintext)` (ciphertext || 16-byte tag)
   - envelope = `phone_pub (65) || nonce (12) || ct`, sent base64url as the body of `POST /api/relay/<sid>`.
3. **Relay** hands the body to the waiting poll (or keeps it in memory for at most 2 minutes),
   then deletes it. One message per session id. No logs of bodies, nothing on disk.
4. **Browser** derives the same key, decrypts, forgets the private key and renders the dashboard.
   The data lives only in that tab's memory.

Only `https` QR codes are accepted by the apps (`http` only for `localhost` during development).

Test vector shared by all implementations: `test/vector.json` (generated by `tools/make-vector.mjs`),
checked by `test/relay.test.mjs` (Node), `WebLinkTest` (Kotlin) and `WebLinkTests` (Swift).
